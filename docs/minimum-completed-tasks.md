# 最低完成任务数量

编辑模式下右键任务节点，选择“编辑”，设置“最低完成任务数量”。这是一个节点内部的任务目标数量，不是前置依赖数量，也不是整个章节的节点数量。

- `0` 保留 FTB Quests 原来的完成规则。
- 正整数表示完成任意指定数量的目标后，整个节点即可完成并进入原生奖励、章节和后续节点解锁流程。
- 数量超过当前目标总数时，实际要求按目标总数计算；没有目标的节点保持原生行为。
- 可选目标只有实际完成后才计数。未完成目标的进度不会被自动补满或清除。
- 前置条件、顺序目标、排斥和重复冷却仍遵守 FTB Quests 的规则。
- 保存降低后的门槛时，已经达标且未锁定的队伍会立即完成节点。提高门槛不会撤销已经完成的节点。
- 节点进度显示已完成目标数相对于门槛的比例，最高为 100%；已完成过的可重复节点保留原生完成次数显示规则。
- QuestLink 显示关联真实任务的进度，自身 ID、坐标和存储身份保持独立。任务描述不需要额外组件。

## 版本与脚本接口

| Minecraft / 加载器 | 已核对的 FTB Quests | 原生任意 N 个目标完成节点 | Quest Enhance 接口 |
| --- | --- | --- | --- |
| 1.20.1 Forge | 2001.4.22 | 无 | 相同 |
| 1.21.1 NeoForge | 2101.1.36 | 无 | 相同 |
| 26.1.2 NeoForge | 26.1.2.8 | 无 | 相同 |

KubeJS 是可选集成；安装后可使用任务节点 Utils：

```js
QuestUtils.setMinimumTaskCount('0123456789ABCDEF', 3)
QuestUtils.getMinimumTaskCount('0123456789ABCDEF')
QuestUtils.setMinimumTaskCount('0123456789ABCDEF', 0)
```

上述方法同时提供 `long` 和字符串 ID 重载。脚本应优先使用字符串，避免 JavaScript 数值精度丢失。

`getMinimumTaskCount` 返回配置数量，无效 ID 返回 `0`。`setMinimumTaskCount` 必须在服务端执行：成功返回 `true`；无效 ID、服务端任务文件不可用或负数返回 `false`。成功写入会保存并同步配置，并检查已有队伍进度是否达到门槛。

1.20.1 和 1.21.1 使用 NBT 保存该属性，26.1.2 使用 JSON5；三个版本保持相同的字段名 `quest_enhance_minimum_tasks` 和网络数量语义。不带该字段的旧任务文件默认使用原生规则。

## 游戏内验收

1. 创建三个勾选目标，门槛设为 `2`。第一个完成时节点不完成，第二个完成时可领取节点奖励并解锁后续节点，第三个目标不应被自动勾选。
2. 设置未完成的前置节点，确认数量门槛不能绕过前置规则。
3. 在已有一个目标完成的节点上把门槛降低为 `1`，确认保存后立即完成；提高门槛后不撤销完成状态。
4. 退出重进世界、重新打开任务书，并用第二个客户端检查配置和进度同步。
5. 在服务端调用脚本接口，检查正数、`0`、负数和无效 ID 的返回值，以及 QuestLink 是否跟随真实节点进度。

构建和独立逻辑测试不能替代上述游戏内界面、领奖和 KubeJS 回归测试。
