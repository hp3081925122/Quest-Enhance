# Quest Enhance 开发

## 先选定版本

把三个工程视为不同版本实现，不要按目录名猜测当前目标：

| 简称 | 工程目录 | 加载器与依赖 | Java | Wrapper |
| --- | --- | --- | --- | --- |
| 1201 | `../Quest Enhance-1201` | Minecraft 1.20.1、Forge 47.4.21、FTB Quests 2001.4.22 | 17 | Gradle 8.8 |
| 1211 | 当前 `Quest Enhance` | Minecraft 1.21.1、NeoForge 21.1.233、FTB Quests 2101.1.28 | 21 | Gradle 8.8 |
| 2612 | `../Quest Enhance-26.1.2` | Minecraft 26.1.2、NeoForge 26.1.2.93、FTB Quests 26.1.2.2 | 25 | Gradle 8.12.1 |

开始修改前执行以下检查：

1. 从用户要求、当前目录、Git 分支和 `gradle.properties` 确认目标版本。
2. 查看目标工作树状态，保留用户已有修改；不要回退、覆盖或顺手格式化无关文件。
3. 查看目标版本的现有实现、依赖源码、反编译结果和日志，确认类、方法、字段、事件和 Mixin 目标真实存在。
4. 禁止把其他 Minecraft 版本、Forge/NeoForge 或不同 FTB Quests 版本的 API 直接搬入目标分支。
5. 跨分支同步时逐版移植并逐版编译；不要把能编译的同名 API 当作行为相同。

## 跨版本 Utils API 契约

功能迁移到 1.20.1 Forge、1.21.1 NeoForge 或 26.1.2 NeoForge 时，优先保持 `QuestUtils`、画布 Utils 和任务节点 Utils 的公开方法名一致。方法名、参数顺序、字符串 ID 重载、返回值语义和失败约定应视为跨版本脚本 API 契约；加载器差异只能放在内部适配实现，不要为同一能力随意改成另一套命名。

新增 Utils 前先在三个分支分别检查现有接口，迁移时沿用已有名称并补齐缺失重载。若某个版本的 FTB API 确实无法提供完全相同的能力，保留最接近的公共签名或显式记录版本差异，不要静默改变同名方法的含义；同时更新 Wiki 的版本兼容表和示例。长整型对象 ID 在 KubeJS 边界统一提供字符串重载，避免脚本因 JavaScript 数值精度丢失而产生跨版本差异。

跨版本迁移的最低验收要求是：逐个分支编译对应 Utils，比较公开方法清单，运行各分支的 KubeJS 回归脚本，并确认成功、失败、空对象和客户端/服务端边界的行为一致。只有内部实现确实不同而公共调用方式保持不变时，才算完成 Utils 迁移。

## 按证据处理问题

修复 bug 时按以下顺序执行：

1. 先复现或读取相关日志，再沿调用、绘制、命中、网络和序列化路径查看源码，确认起因。
2. 加入能区分关键分支和对象身份的最小调试。日志内容使用英文，避免在每帧绘制、鼠标移动或高频事件中刷屏。
3. 让用户测试时，列出本次具体调整、触发步骤、预期结果和需要观察的项目。
4. 确认修复完全后，删除临时调试、失败尝试、已被最终方案覆盖的补丁和不再需要的兼容分支。
5. 回看最终 diff，确保只保留解释得通且仍参与最终行为的改动。

不要为只调用一次且没有独立抽象价值的逻辑创建方法。KubeJS 脚本禁止定义只调用一次的函数。Java 代码的小逻辑块按项目规则使用简短中文注释，不写英文注释；调试日志仍使用英文。所有文本文件保持 UTF-8。

## 新功能四项检查

每次新增功能、扩展现有功能或改变用户可见行为时，必须逐项分析并在交付中报告：

1. **画布**：画布是否需要入口、展示、编辑、命中、选择、移动、复制、删除或持久化支持；能否在当前版本实现。
2. **任务描述**：章节/任务描述内部是否需要对应组件、构造、渲染、交互和序列化支持；能否在当前版本实现。
3. **链接任务**：功能是否会遇到 `QuestLink`，是否必须兼容其独立身份、位置、按钮、绘制和存储。
4. **Utils**：是否能且应该补入 KubeJS Utils；明确属于画布元素 Utils、任务节点 Utils，或两者都属于。

即使结论是“不需要”或“当前不能做”，也要说明依据。不要只因为本次需求只点名一个界面，就跳过其余三项。

## 区分两类 Utils

### 画布元素 Utils

评估并覆盖普通任务、`QuestLink`、图片、GIF、视频、文字和辅助点。根据当前版本已验证的能力提供创建、查询、修改、移动、尺寸、形状、层级、复制、删除、显示和序列化操作。不要把画布元素误当成玩家任务进度。

### 任务节点 Utils

评估并覆盖章节、任务、目标、奖励、依赖、状态、进度、描述和可见性。任务节点能力包括但不限于：

- 查询任务、章节、状态、进度和依赖。
- 完成、重置任务与修改玩家进度。
- 判断前置任务是否完成以及完成数量。
- 根据任务 ID 打开任务书页面。
- 动态创建、复制、修改和删除章节、任务、目标、奖励与依赖。
- 隐藏或取消隐藏任务和章节。
- 构造描述组件，包括文本、图片、GIF、视频、物品等当前版本支持的组件。

把“任务书结构修改”和“玩家/队伍进度修改”分开设计。所有写操作在服务端执行，使用目标版本 FTB Quests 已验证的保存、变更通知和同步路径；不要仅修改客户端对象或未经确认直接改集合。动态创建能力优先覆盖编辑界面已有且可以可靠持久化的手动操作。

描述组件构造接口负责处理 JSON 转义、Base64、尺寸、对齐和物品 NBT，不把这些易错细节交给脚本作者重复拼接。长整型任务、章节、目标和奖励 ID 在 KubeJS 边界使用字符串，避免 JavaScript 数值精度丢失。

## 保持 KubeJS 可选

把 KubeJS 视为可选集成，而不是模组启动前提：

- 公共类和纯 FTB Quests 功能不得在字段、方法签名、静态初始化或类继承中泄漏 KubeJS 类型。
- 将 KubeJS 注册和包装代码隔离到兼容包，并只在确认 KubeJS 已加载后进入该代码路径。
- 同时核对构建依赖与模组元数据的可选声明。
- 至少验证安装 KubeJS 时脚本可注册；涉及加载边界时再验证移除 KubeJS 后模组仍能启动。
- 不在服务端可达代码中引用客户端类。打开 GUI 等客户端行为通过当前版本已验证的网络路径触发。

优先用 `run/kubejs/server_scripts/quest_utils_test.js` 做全量回归。测试脚本使用手持基岩右键触发，第一次创建并打开测试内容，第二次清理临时章节；新增 Utils 后同步扩展脚本，并确保失败项能明确显示。

## 兼容 QuestLink

涉及画布节点、选择、菜单、绘制、命中、移动、复制、删除、序列化或装饰线时，同时完整读取 [`../questlink-compatibility/SKILL.md`](../questlink-compatibility/SKILL.md)。以下规则不可省略：

- 把 `QuestLink` 当作独立画布节点，不要替换为其 `linked_quest` 或关联真实任务。
- 保留链接任务自己的 ID、坐标、尺寸、形状和 `quest_links` 序列化身份。
- 普通任务、链接任务和辅助点使用不同键空间；沿用 `q:<id>`、`l:<id>` 和辅助点 UUID。
- 从继承自 `QuestButton` 的链接按钮进入功能时，确认实际按钮和实际链接对象，避免误用继承字段里的真实任务。
- 删除、复制或隐藏前置线时同时检查真实任务与链接任务引用，并清理缓存、选择状态和持久化数据。
- 网络消息若只接受真实任务 ID，先查源码确认原生语义；不要伪造链接任务数据。

## 处理媒体与描述组件

图片、GIF 和视频功能必须分别检查画布与任务/章节描述两条路径。检查内容包括资源定位、远程/本地资源、尺寸与对齐、编辑和非编辑模式、悬停与点击命中、加载失败占位、缓存释放、复制粘贴及序列化。

不要因为 GIF 或视频路径正常，就假设静态图片共享相同行为。FTB Quests 的图片标题或悬停显示可能受原版配置控制；先确认原版开关语义，再决定是否需要修复，避免接管应由整合包作者配置的行为。

## 验证与运行

优先使用目标工程自己的 `gradlew.bat` 和已配置 Java 工具链。在 PowerShell 中从最小验证开始：

1. Java 逻辑改动运行 `./gradlew.bat compileJava`。
2. 资源、Mixin 配置或模组元数据改动追加 `./gradlew.bat processResources`。
3. 跨模块或准备交付 Jar 时运行 `./gradlew.bat build`。
4. Mixin、类加载、GUI、绘制、命中、输入、网络或 KubeJS 运行行为必须启动对应 `runClient` 实测。

启动 `runClient` 前检查同一工程是否已有客户端、IDE 或 Gradle 进程占用构建产物。遇到 `Unable to delete ...jar` 时先定位并停止持有该文件的进程，不要盲目删除整个 `build`。2612 必须使用 Java 25 与 Gradle 8.12.1，避免 NeoForge 变体选择冲突。

运行后检查 `run/logs/latest.log`、KubeJS 脚本加载结果和相关英文调试。不要把“进程仍在运行”等同于功能通过；按具体测试步骤确认界面、数据保存、重进世界和重新打开任务书后的状态。

## 交付前检查

- 目标版本、加载器和依赖 API 均由当前源码或依赖证明。

- KubeJS 仍是可选依赖，长 ID 使用字符串。
- `QuestLink` 没有被降级成真实任务。
- 临时调试和无用修复已经清除。
- 已执行与风险匹配的最小验证，并如实报告未执行或仍需用户实测的部分。
- 未覆盖用户工作树中的已有修改，跨分支变更分别验证。
